# Carry preparation distribution audit

The carry learner sees a much narrower physical state distribution than the full task. The geometric100 dataset contains **835 episodes / 228,059 transitions, all foam object14**, prepared with the reference grasp and point-cloud seed42. Online scene rotation and isolated checkpoint selection use that same preparation. Across181 dataset episodes beginning at the original carry handover, finger positions and payload offset are identical. Failed carry trajectories are present (6 episodes), but other objects and learned-grasp preparation failures are absent.

At that reference handover the two finger joint positions sum to49.64mm. Learned full-task foam grasps instead sum to74–76mm on8/12 validation layouts, reflecting a different pinch orientation even for the trained object. Across the59 full-system cases that reach navigation,42 have a finger position beyond the entire recorded training range;53 have at least one of the five finger/payload features beyond it. These component ranges describe missing coverage; they are not a calibrated failure classifier, and many such grasps still succeed. The actor explicitly receives these measurements, so this is both a physical retention mismatch and an input-distribution mismatch.

The selected geometric100 checkpoint passes10/12 isolated reference-foam carries but8/12 learned-foam full tasks on the same layouts. Foam005 and008 pass isolated carry and lose the learned grasp. Point-cloud seed, grasp, and resulting posture differ, so this comparison does not identify one cause by itself. The earlier matched BC/SAC system comparison fixes all60 physical prefixes and still changes42/60 to35/60 success: navigation actions also matter.

Repeated route oscillation is a separate, visible failure mode. In geometric100, the eight timeouts have median13.4° heading change per recorded moving interval, versus2.1° among successes. However,11/16 carry grip losses have **no >120° motion reversals**, and14/16 occur before2,000 carry calls. Apple000 loses contact within62 calls after already shifting16.2mm during the planned handover; apple010 loses within200 calls after14.6mm handover drift. Those failures cannot be explained by a long navigation loop. In addition,98.94% of teacher labels have action norm>.95: current supervision mostly teaches full speed, with no varied-payload evidence for slower retained transport.

I rank inadequate grasp/handover coverage above simple route jitter as the explanation for early and non-loop retention failures. Maze recovery remains the leading explanation for the eight horizons and amplifies some late losses. The evidence does not justify replacing the measured grip inputs, adding a hidden pause, or prescribing a new speed rule.

The minimal next support is an explicitly versioned TRAIN preparation mode: fresh original scene → shared geometric pregrasp → frozen54-state learned grasp at24cm goal → existing50-call hold → shared planned carry posture → `GeneralCarryEnv.bind`, with no reset between stages. The grasp checkpoint hash, proposal mode, point seed, object, map hash, lift goal, and controller scale belong in the preparation/cache key. Rotate all five objects; retain each failed preparation and its costs in the fixed case denominator. Do not require a successful full teacher route just to admit a handover: current `_build_physical_bank` raises on route failure, which would hide the weak grips we need to study. Start from valid handovers, preserve terminal failure transitions, and add later curriculum snapshots only when physically reached. Keep the foam/reference mode as an explicit compatibility control.

A bounded feasibility check has been authorized: first two frozen TRAIN layouts × five objects, selected clearance01 learned grasp, then100 teacher carry decisions (at most500 native calls). This is preparation/data feasibility, not a new training branch or full-task result. No held-out layouts are used.

Audit artifacts: `runs/phase2_carry_distribution_audit01/artifacts/{summary.json,audit.py}`. The read-only audit executed zero simulator calls. Full-system traces sample every5 native calls and are offset from policy-decision boundaries; heading changes above are measured motion proxies, not recorded actions. The teacher-action statistics come directly from the immutable training pickle.

## Fixed TRAIN feasibility result

`runs/phase2_learned_handover_preflight01` completed **10/10 prepared handovers and10/10 retained short transports**. The frozen cases are train000/train001 crossed with all five objects. Grasp uses the selected clearance01 checkpoint at12,000 online decisions (`fa7b8d54cdc916d6e68753721993b66b7e571bf09af84e70cf4e4030618dfbe2`),24cm lift, and clearance-v2 proposals. Both cans selected checked tilted proposals. All10 cases had zero recorded wall or robot-table contact calls. No failed case was replaced; geometrically rejected proposal candidates remain in each case's proposal diagnostics.

The run executed13,487 native calls:8,487 for original-start preparation and5,000 for teacher transport. This is67,435 action physics ticks plus4,800 initial settling ticks, **72,235 total**. Each successful teacher segment contains100 decisions/500 native calls, reaching approximately7.2m of route travel. These are TRAIN feasibility outcomes, not full-task or learned-navigation success.

The handovers cover finger-position sums37.8–87.8mm, including both foam pinch orientations (49.1 and75.3mm). Peak payload displacement during teacher transport reaches15.5mm for foam and12.7mm for can, despite retained bilateral contact. Banana000 ends near the pad edge. Therefore the next collection should preserve real trajectories and failures throughout the route; these short successes do not justify screening out later unstable examples or claiming robust transport.

`scripts/phase2_learned_handover_preflight.py` is diagnostic-only. It subclasses the shared system to reuse the exact original-start prefix and binds the existing carry adapter without stepping or resetting. Only the carry segment uses a disclosed geometric data teacher; reaching is never called. Artifacts include frozen checkpoint/source hashes, every-native-call contact/force traces, real carry action/observation/reward/terminal arrays, and complete cost totals. Four focused tests cover exact carry budget, preserved terminal failures, fixed case denominators, and the explicit distinction from full-task success.
